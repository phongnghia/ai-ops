CI/CD Tools — Bức tranh toàn cảnh cho Newbie

Nền tảng · CI/CD
CI (Continuous Integration) = tự động build + test mỗi khi push code. CD (Continuous Delivery/Deployment) = tự động deploy sau khi CI pass. Mục tiêu: rút ngắn feedback loop từ "viết code" → "chạy trên production".

Jenkins

Self-hosted

Ông già CI/CD. Free, linh hoạt, 1800+ plugins. Chạy trên server của bạn. Pipeline viết bằng Groovy (Jenkinsfile).

SaaS / Cloud

YAML workflow on: push / PR

Vấn đề thực tế — Tại sao CI/CD cần AI?

Pain Points · Thực trạng
Scenario: 2am trước ngày release. Jenkins báo đỏ. Slack ping bạn. Bạn làm gì tiếp theo?
  • Mở Jenkins Console: 3.000 dòng log. Lỗi thật ẩn giữa hàng trăm dòng [INFO] vô nghĩa.

AIOps Landscape — Thị trường đang làm gì?

Industry · Tools
AIOps (thuật ngữ Gartner, 2017) = dùng AI/ML để tự động hóa IT Operations. Không chỉ là "chatbot hỏi AI" mà là anomaly detection, event correlation, root cause analysis, và auto-remediation. Thị trường 2024: ~$3.5B, dự báo tăng 3× vào 2029.

Observability + AI

Dynatrace Davis AI

Causal AI — tự tương quan hàng nghìn events tìm root cause mà không cần human correlation. Dùng tại BMW, Vodafone, Delta Airlines. Giá: từ $69/8GiB host/month.

Datadog Watchdog + AI Assistant

Anomaly detection trên metrics/logs/traces. AI Assistant (GPT-4 powered) — query bằng ngôn ngữ tự nhiên: "Tại sao p99 tăng?". Dùng tại Shopify, Peloton.

New Relic AI

NRQL AI tự suggest query. Giao diện chat debug incident. Alert correlation tự động giảm noise 60–80%.

Incident Management + AI

PagerDuty AIOps

Alert noise reduction — filter 90% redundant alerts. Intelligent grouping: 200 alerts → 1 incident. Auto-triage theo severity. Dùng tại Netflix, Twilio.

BigPanda AIOps

Event correlation từ nhiều nguồn (Nagios, Zabbix, CloudWatch, Prometheus). ML tự học topology. Predict maintenance windows.

OpsRamp / Moogsoft

Hybrid infra monitoring + AI root cause analysis. Predict failures trước khi xảy ra dựa trên historical patterns.

CI/CD + AI trực tiếp

GitHub Copilot for CLI

gh copilot explain "$(cat error.log)" — giải thích lỗi terminal. gh copilot suggest đề xuất lệnh fix. Tích hợp trực tiếp vào developer workflow.

Harness AI / AIDA

AI tích hợp vào Harness CD pipeline. Tự động phân tích pipeline failure, suggest remediation, AIDA review PR và propose code fix.

CircleCI AI Insights

Phân tích flaky tests, predict test failure, suggest optimization cho pipeline duration và cost.

Điểm chung: Tất cả tools trên đều SaaS đắt tiền ($50–$500/host/month), closed-source, và bạn không kiểm soát được AI logic. Workshop này: $0, self-hosted, open-source, tích hợp bằng vài dòng bash.

Tiếp theo: Đã thấy landscape — giờ so sánh chi tiết: khi nào nên mua SaaS, khi nào nên tự build?

Dùng SaaS AIOps khi nào?

  • Team 50+ người, cần full observability stack (metrics + logs + traces + incidents)
  • Budget lớn, không muốn maintain infra, cần compliance certifications (SOC2, HIPAA)
  • Ví dụ thực tế: Dynatrace tại BMW, Datadog tại Shopify, PagerDuty tại Netflix

Tự build (như workshop này) khi nào?

  • Startup hoặc SME — budget hạn chế, muốn bắt đầu nhanh trong 1 buổi chiều
  • Data nhạy cảm cao — log không được ra ngoài (banking, healthcare, government)
  • Đã có Jenkins — chỉ cần thêm AI layer, không muốn đổi cả platform
  • Muốn học hiểu AI-Ops từ bên trong trước khi đầu tư SaaS

LLM + RAG + AI Gateway — 3 Khái Niệm Cốt Lõi

AI Concepts · Architecture

LLM

Large Language Model — mô hình train trên hàng tỷ dòng text (GitHub, StackOverflow, docs). Nhận text input → trả text output.

Tại sao phù hợp với log analysis? Vì LLM đã đọc hàng triệu GitHub issues, Maven error reports, JVM stack traces — nó nhận ra pattern lỗi ngay lập tức.

Input: "cannot find symbol: calculateDiscount"
Output: "Method renamed, update call at line 47"

gpt-4o-mini gemini-2.0-flash qwen2.5-coder (Ollama)

RAG

Retrieval-Augmented Generation — trước khi hỏi AI, tìm kiếm tài liệu liên quan và nhét vào context. Giống cho AI "tờ gian lận" trước khi thi.

Tại sao cần RAG? LLM không biết lỗi này đã xảy ra ở build #98 tháng trước và cách fix thế nào — chỉ team bạn biết. RAG nhét kiến thức đó vào prompt.

DB: Build #98 → "renamed method" → PR#44
Prompt: "Similar past failure: [DB result]. Current: [log]"

PostgreSQL pgvector keyword / vector search

AI Gateway

LiteLLM = proxy đứng giữa code và LLM providers. Backend gọi 1 endpoint OpenAI-compatible — LiteLLM tự route, retry, fallback.

Tại sao cần Gateway? Không vendor lock-in. Azure fail → Gemini → Ollama tự động. Một API key quản lý tập trung thay vì scatter qua nhiều services.

Code Step 1 — Jenkins Preprocess Log

Code · Bash / Jenkins
Trước khi gửi log cho AI, phải lọc 95% nhiễu. 3.000 dòng → 30 dòng lỗi thực sự. Đây là bước tiết kiệm nhất: giảm token, giảm chi phí, tăng chất lượng phân tích.

Jenkinsfile — post{failure} block

Jenkinsfile 
post {
  failure {
    script {
      try {
        sh '''#!/usr/bin/env bash
        set -euo pipefail
        source "${SCRIPTS_DIR}/analyze.sh"
        python3 "${SCRIPTS_DIR}/notify.py"
        '''
      } catch (Exception err) {
        // AI-Ops never blocks build result
        echo "AI Ops skipped: ${err}"
      }
    }
  }
}

try/catch rule: AI analysis là enhancement, không phải dependency. Backend down hoặc LLM timeout không được làm hỏng build result của developer.

preprocess_log.sh — log sources

read_log_tail() {
  if [[ -n "${JENKINS_LOG_FILE:-}" ]]; then
    tail -n 100 "${JENKINS_LOG_FILE}"
    return
  fi
  # Fallback: REST API + basic auth

}
read_log_tail | python3 "${PREPROCESS_PY}"

preprocess.py — filter logic

preprocess.py 
import sys, re

ERROR_PATTERN = re.compile(
    r"(error|fatal|exception|failed|"
    r"traceback|caused by|at\s+\w+\.\w+)",
    re.IGNORECASE
)

lines = sys.stdin.readlines()[-100:]  # last 100
filtered = [l for l in lines
            if ERROR_PATTERN.search(l)]

# Cap at 50 lines to control tokens
output = filtered[-50:] if filtered else lines[-20:]
sys.stdout.write("".join(output))

Code Step 2 + 3 — Backend Orchestration & Prompt Engineering

Code · Python / FastAPI

analysis_service.py — orchestrator

analysis_service.py 
def analyze(self, build_number, cleaned_log, ...):
  # Step 1: RAG search — past similar failures
  rag_ctx = self._retrieve_context(cleaned_log)

  # Step 2: Assemble prompt
  messages = prompt_builder.build(
      cleaned_log, build_number, rag_ctx
  )
  # Step 3: Call LLM via LiteLLM gateway
  result = self._complete(messages)

  # Step 4+5: Save to DB + notify (best-effort)
  self._save_best_effort(build_number, ...)
  self._notify_best_effort(build_number, ...)

  return AnalysisResult(text=result.text, ...)

Graceful Degradation: _save_best_effort và _notify_best_effort log ERROR nhưng không throw exception. Caller luôn nhận kết quả dù DB hoặc Slack bị down.

litellm_client.py — gateway call

litellm_client.py 
def complete(self, messages):
  resp = self._http.post(
      f"{self._url}/chat/completions",
      json={"model": "log-analyzer",
            "messages": messages},
      headers={"Authorization":
               f"Bearer {self._api_key}"},
      timeout=self._timeout,
  )
  choice = resp.json()["choices"][0]
  return LLMResult(
      text=choice["message"]["content"],
      provider=resp.headers.get("x-litellm-model-id")
  )

prompts.py — structured output

prompts.py 
SYSTEM_PROMPT = (
  "You are a CI/CD failure analysis expert.\n"
  "Always use plain text — no markdown.\n"
  "Use exactly these 3 section labels:\n\n"

Tại sao Plain Text thay vì Markdown?

**bold** và ## Header hiển thị raw trong Slack, Teams, Jenkins console. Emoji labels (🚨) hoạt động universal trên mọi platform.

prompt_builder.py — assembler

prompt_builder.py 
def build(cleaned_log, build_number, rag_context):
  user_parts = [
      f"Build: {build_number}",
      f"Log:\n{cleaned_log}",
  ]
  if rag_context:
      user_parts.insert(0,
          "Past failures:\n" + rag_context)
  return [
      {"role": "system", "content": SYSTEM_PROMPT},
      {"role": "user",
       "content": "\n\n".join(user_parts)},
  ]

Prompt layers: System role → RAG context (optional) → Current log. Thứ tự này giúp LLM ưu tiên past fixes khi có RAG data.

Extend AI-Ops — ArgoCD + Coolify Integration

Extend · GitOps / PaaS
Backend AI-Ops là một generic HTTP service. Bất kỳ CI/CD tool nào — dù là ArgoCD, Coolify, GitHub Actions hay Bitbucket — đều có thể tích hợp AI analysis bằng cùng một pattern: detect fail → gửi log → nhận phân tích.

ArgoCD

GitOps CD cho Kubernetes

K8s native

ArgoCD sync app từ Git lên K8s. Khi sync fail — image lỗi, quota exceeded, manifest sai — tự động gọi AI phân tích nguyên nhân.

Option A — Notification Webhook

Dùng argocd-notifications: cấu hình trigger on-sync-failed → gửi webhook POST đến /api/analyze-log với app name + sync conditions. Zero code, chỉ cần YAML config.

Option B — SyncFail Hook Job

Tạo K8s Job annotate argocd.argoproj.io/hook: SyncFail. Job chạy container curl để gọi backend AI và post kết quả lên Slack.

Coolify

Self-hosted PaaS trên VPS

Docker-based

Coolify deploy Docker app lên VPS, tự cấp SSL, zero DevOps. Khi deploy fail, trigger AI qua webhook hoặc build script.

Option A — Deployment Webhook

Vào Settings → Webhooks trong Coolify UI, chọn event deployment.failed, điền URL backend AI. Không cần code, không cần server config.

Option B — Post-deploy Script

Thêm pre/post-deploy command trong Application settings: script bash kiểm tra exit code, nếu fail thì curl gọi /api/analyze-log với deploy log.

Pattern tổng quát — áp dụng cho mọi CI/CD tool

Detect fail

Hook / Webhook / Trigger khi build/deploy fail

Filter log

Lấy log liên quan, loại bỏ noise

POST /api/analyze-log

Cùng backend AI — không đổi code

Notify

Slack / Teams / console output

Roadmap & OSS Ecosystem — Tương lai của AI-Ops

Roadmap · Open Source

Nhược điểm của v1 — sau khi xem demo

Chỉ đọc log — không hiểu context hệ thống

AI chỉ thấy log text. Không biết trạng thái K8s pods, git history gần nhất, metrics CPU/memory, hay infrastructure topology. Đôi khi root cause thật nằm ở infra, không phải code.

Passive Advisor — kỹ sư vẫn phải tự fix

AI đưa ra "Fix Steps" dạng text. Kỹ sư đọc → tự mở file → tự sửa → tự commit. Giảm thời gian debug nhưng không giảm được effort thực thi fix.

RAG còn sơ khai — vector search chưa thật sự semantic

Placeholder embedder hiện tại dùng keyword match. Không tìm được lỗi "tương tự ngữ nghĩa" nếu khác từ khóa. Cần production-grade embedder mới khai thác hết sức mạnh RAG.

Latency cao với Ollama — UX kém khi chạy local

Ollama CPU inference mất 60–120s. Trong pipeline CI/CD, mỗi build fail đều phải chờ. Cloud LLM giải quyết nhưng phát sinh chi phí và data privacy concern.

Single-request — không có memory giữa các phân tích

Mỗi lần build fail là 1 request độc lập. AI không biết build trước đã gợi ý gì, đã fix được chưa, hay đang ở step nào trong quá trình debug.

Từng nhược điểm → Solution tương ứng

MCP (Model Context Protocol)

Kết nối AI Agent trực tiếp vào Git API, K8s API, Grafana. AI tự git log, kubectl describe pod, đọc metrics → hiểu toàn bộ context hệ thống trước khi phân tích.

Agentic Auto-Healing — AI tự tạo PR fix

AI Agent không chỉ đề xuất — tự tạo branch, edit file, commit, mở Pull Request trên GitHub/GitLab. Kỹ sư chỉ review & merge.

Real Embedder + Semantic RAG

text-embedding-3-small hoặc Ollama embedder. Cosine similarity thật sự → tìm lỗi "tương tự ý nghĩa" dù dùng từ khác nhau.

Streaming + Caching

SSE streaming cho UX real-time. LiteLLM semantic cache: lỗi giống nhau trả kết quả cached trong <0.5s, không gọi LLM thêm.
